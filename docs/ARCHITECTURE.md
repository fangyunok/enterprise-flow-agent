# EnterpriseFlow 架构

## 职责与信任边界

模型输出只允许订单 ID、成本中心、日期、目的地和备注。`TripFields` 拒绝额外字段；模型没有金额、租户、员工身份、审批许可等输出槽位。业务服务再次验证输入，并从数据库读取金额、订单归属和有效制度。

演示登录从固定合成身份中选择员工，服务端签名会话绑定其身份。MCP 工具服务器由服务端为该身份创建，工具参数没有员工或租户字段。服务每次操作仍从数据库验证身份，查询必须同时符合员工归属和租户范围。

## 两类持久化

| 数据 | 存储 | 含义 |
| --- | --- | --- |
| 订单、制度、偏好、草稿、确认、提交、审计事件 | 业务 SQLite 文件 | 业务记录及事务完整性 |
| LangGraph 状态与人工暂停点 | 独立 `*-checkpoints.sqlite` 文件 | 同一个 `run_id` 的流程恢复 |

`WorkflowEngine` 使用真实 `StateGraph` 与 `AsyncSqliteSaver`，通过异步调用和 SQLite 保存状态。状态包含字段、草稿、待确认内容及工具耗时。重启后重新登录演示身份，读取原任务并继续；会话签名密钥在进程重启后更新，已有网页会话需要重新登录。

已明确保存的成本中心在业务库中跨任务存在，这是项目的长期偏好。流程字段和草稿属于单任务短期状态。当前显式成本中心覆盖已保存偏好，偏好也需再次通过当前权限检查。

## 制度与金额

检索先进行租户、部门及生效区间 SQL 过滤，再排序相关关键词。真正参与核算的条款还需匹配城市和费用类型；更具体的部门制度优先于通用制度。相同优先级有多个条款时报告冲突，不任意选择。

金额用整数分表示，不交由模型计算。住宿按晚拆分，在跨制度生效日的订单中分别应用每日条款。除不尽的分按确定顺序分配；总分保持不变。订单和来源快照参与内容摘要，提交前重新核算，来源发生变化时阻止使用旧草稿。

## 确认与提交

审批暂停点显示草稿版本和 SHA256 内容摘要。恢复审批必须提供当时展示的版本和摘要，服务还会检查当前草稿和来源。编辑后的草稿需要刷新暂停点并重新确认。

创建提交使用写事务、草稿唯一提交约束及幂等键。相同请求重试返回原编号；幂等键复用到不同内容时返回冲突。项目保证的是这套单机 SQLite 事务内的提交一致性，未演示分布式消息、外部支付或跨库事务。

## 调度与失败

每个任务使用服务端锁序列化恢复，执行容量受限制，工具和模型请求有超时。模型不可用、受限字段校验失败、制度不足、越权或过期确认都保留失败状态或返回明确错误。不会把工具错误转换成成功提交。

这版办理流程固定编排，模型在流程中用于字段提取。另有独立只读制度问答接口：先通过身份绑定 MCP 检索，再将授权条款交给 Qwen/API 生成受限 JSON，校验引用来源 ID、回答片段和来源原文片段。引用结构有效不等于语义被证据支持；返回 `semantic_support_verified=false` 与 `pending_review`，需要人工核查。问答不能确认或提交草稿，离线模式只返回条款预览。

项目没有实现模型自由规划工具序列或多智能体。后续可在相同工具和事务边界内增加采购、资产领用等流程，但本版只实现一个示范流程。
