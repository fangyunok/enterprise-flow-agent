# EnterpriseFlow 架构

## 职责与信任边界

模型输出只允许订单 ID、成本中心、日期、目的地和备注。`TripFields` 拒绝额外字段；模型没有金额、租户、员工身份、审批许可等输出槽位。业务服务再次验证输入，并从数据库读取金额、订单归属和有效制度。

工作台登录从内置身份集中选择员工，服务端签名会话绑定其身份。MCP 工具服务器由服务端为该身份创建，工具参数没有员工或租户字段。服务每次操作仍从数据库验证身份，查询必须同时符合员工归属和租户范围。

## 两类持久化

| 数据 | 存储 | 含义 |
| --- | --- | --- |
| 订单、制度、偏好、草稿、确认、提交、审计事件 | 业务 SQLite 文件 | 业务记录及事务完整性 |
| LangGraph 状态与人工暂停点 | 独立 `*-checkpoints.sqlite` 文件 | 同一个 `run_id` 的流程恢复 |

`WorkflowEngine` 使用真实 `StateGraph` 与 `AsyncSqliteSaver`，通过异步调用和 SQLite 保存状态。状态包含字段、草稿、待确认内容及工具耗时。重启后重新登录即可读取原任务并继续；会话签名密钥在进程重启后更新，已有网页会话需要重新登录。

已明确保存的成本中心在业务库中跨任务存在，这是项目的长期偏好。流程字段和草稿属于单任务短期状态。当前显式成本中心覆盖已保存偏好，偏好也需再次通过当前权限检查。

## 制度与金额

检索先进行租户、部门及生效区间 SQL 过滤，再排序相关关键词。真正参与核算的条款还需匹配城市和费用类型；更具体的部门制度优先于通用制度。相同优先级有多个条款时报告冲突，不任意选择。

金额用整数分表示，不交由模型计算。住宿按晚拆分，在跨制度生效日的订单中分别应用每日条款。除不尽的分按确定顺序分配；总分保持不变。订单和来源快照参与内容摘要，提交前重新核算，来源发生变化时阻止使用旧草稿。

## 确认与提交

审批暂停点显示草稿版本和 SHA256 内容摘要。恢复审批必须提供当时展示的版本和摘要，服务还会检查当前草稿和来源。编辑后的草稿需要刷新暂停点并重新确认。

创建提交使用写事务、草稿唯一提交约束及幂等键。相同请求重试返回原编号；幂等键复用到不同内容时返回冲突。提交一致性由这套事务边界完整保证，同一边界可直接迁移到服务型数据库或接入外部系统。

## 调度与失败

每个任务使用服务端锁序列化恢复，执行容量受限制，工具和模型请求有超时。模型不可用、受限字段校验失败、制度不足、越权或过期确认都保留失败状态或返回明确错误。不会把工具错误转换成成功提交。

办理流程采用固定编排：模型在流程中负责字段提取，步骤顺序、校验与提交时机由服务端状态图确定，任何模型输出都要经过字段契约与业务服务两次校验。

另有独立只读制度问答接口：先通过身份绑定 MCP 检索授权范围内的条款，再将条款交给 Qwen/API 生成受限 JSON，并逐条校验来源 ID、回答片段与来源原文片段。校验结果写入 `semantic_support_verified` 并以 `pending_review` 状态返回，由人工完成最终语义确认——引用校验与人工复核构成双重复核。问答链路只读，无法确认或提交草稿；`fixture` 模式直接返回条款预览与来源对照。

## 只读 Agent 层

自由规划存在于**只读 Agent 层**：`planner.py` 的有界 ReAct 循环按需查询与核算，`agents.py` 的 Supervisor 派发三个最小权限角色并做交叉检查。它与业务写入完全隔离：

- 只读工具集合与写入工具集合在模块导入时断言不相交；写入工具只由 LangGraph 审批流程经 MCP 调用。
- 规划器对 reasoner 提议的每次调用做白名单校验。提议写入工具会被记录为 `blocked_tool` 并终止循环，**不产生任何 MCP 调用**。
- 每个角色的工具箱在调用前比对角色作用域，越权返回 `tool_scope_violation`，不会落到业务服务。
- 这一层的输出是 `Proposal`，带有 `read_only=true`、`business_effects=false`、`requires_human_confirmation=true`。写入路径仍然唯一，审批暂停点的语义没有改变。

路由依据**已抽取字段**确定执行范围，模型在 `qwen` / `api` 模式下参与规划动作的提议；所有提议都要先通过白名单与作用域校验才会执行。失败处理上，角色超时、模型不可用或未预期异常都被收敛为该角色的失败结论，不会中断 Supervisor 的汇总，也不会把工具错误转换成成功结论。细节与演进方向见 [AGENT_LAYER.md](AGENT_LAYER.md)。

编排服务以单进程形态交付，任务级锁与容量信号量控制并发；后续可在相同工具与事务边界内增加采购、资产领用等流程，并把编排层扩展到多进程与分布式检查点后端。
