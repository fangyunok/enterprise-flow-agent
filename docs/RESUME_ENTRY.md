# 简历与面试材料

## 项目名称

**EnterpriseFlow：企业业务流程编排与执行平台**

技术：Python、LangGraph、MCP、SQLite、Pydantic、Starlette、HTTPX。

## 当前可使用的项目描述

基于 LangGraph 和 MCP 开发企业业务流程编排原型，以合成差旅费用申请演示字段补充、制度检索、草稿生成、人工确认与事务提交；使用 SQLite 文件检查点恢复中断任务，并将身份和金额校验放在确定性业务层。

- 将 MCP 工具绑定服务端身份，在数据库查询中按员工、租户、部门和生效日期限制订单及制度，提供适用条款版本与来源对照。
- 实现只读 Agent 层：有界 ReAct 规划循环按需查询与核算，对写入工具的提议在执行前被白名单拦下；Supervisor 派发三个最小权限角色做订单核对、条款检索与确定性核算，再对结论做交叉检查并按 blocking / warning 分级。该层输出的 `Proposal` 不带任何业务写入。
- 实现只读制度问答，将授权条款输入模型并验证引用 ID 和原文片段；答案进入人工核查状态，问答无法触发业务提交。
- 使用整数分进行费用核算，结合草稿版本、SHA256 内容摘要、来源重校验、写事务和唯一约束处理旧确认与重复提交。
- 区分单任务状态与长期偏好，支持用户明确保存和删除成本中心；提供本地网页、锁定依赖与脱离源码目录的安装验证。
- 通过 114 项测试及 Ubuntu/Windows × Python 3.11/3.12 四组 GitHub CI，覆盖授权、制度版本、草稿确认、重复提交、真实 MCP、检查点恢复、HTTP 接口、只读规划的预算与越权阻断、多角色的作用域约束与冲突检测，并验证 wheel 在源码目录外运行。

真实 Qwen 与模型质量仍待验证，不能写“Qwen 端到端验证通过”或宣称生产上线。模型驱动规划只做了协议层验证；`fixture` 模式下的确定性指标见 `results/agent_layer_benchmark.md`。跨系统 CI 记录见 [实际运行结果](https://github.com/fangyunok/enterprise-flow-agent/actions/runs/37118933475)。

## 演示顺序

1. Alice 的两笔订单形成草稿，解释每晚住宿上限和超额部分。
2. 在审批处关闭程序、重新运行并登录，恢复原任务。
3. 修改草稿后用旧确认提交，展示版本冲突；刷新后重新确认。
4. 重复提交仅获得一份申请记录。
5. 切换 Bob 或另一租户身份，证明无法访问 Alice 的订单、草稿与任务。

## 面试时要说清楚

这版审批流程仍然是固定编排，模型只负责提取业务字段；没有让模型直接决定身份、金额或绕过审批。Agent 层能自由决定「下一步查什么」，但只能在只读白名单内：写入工具的提议会被规划器在执行前拦下，业务写入路径只有一条。使用关键词制度检索和结构化过滤，没有宣称向量 RAG。演示账号、制度和订单全为自建合成数据；模拟申请编号不是实际审批或付款。

被追问时不要含糊的两点：

- 测试数是 **114 项**，其中只读规划 24 项、多角色协作 22 项；不要沿用更早的数字。
- 多角色是**确定性路由 + 模型可选提议**，不是模型自主编排班组：路由依据是已抽取字段，代码在 `Supervisor._route`；模型只在 `qwen` / `api` 模式下提议下一步动作。
