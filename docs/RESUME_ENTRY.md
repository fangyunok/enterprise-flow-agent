# 简历与面试材料

## 项目名称

**EnterpriseFlow：企业业务流程编排与执行平台**

技术：Python、LangGraph、MCP、SQLite、Pydantic、Starlette、HTTPX。

## 当前可使用的项目描述

基于 LangGraph 和 MCP 开发企业业务流程编排原型，以合成差旅费用申请演示字段补充、制度检索、草稿生成、人工确认与事务提交；使用 SQLite 文件检查点恢复中断任务，并将身份和金额校验放在确定性业务层。

- 将 MCP 工具绑定服务端身份，在数据库查询中按员工、租户、部门和生效日期限制订单及制度，提供适用条款版本与来源对照。
- 实现只读制度问答，将授权条款输入模型并验证引用 ID 和原文片段；答案进入人工核查状态，问答无法触发业务提交。
- 使用整数分进行费用核算，结合草稿版本、SHA256 内容摘要、来源重校验、写事务和唯一约束处理旧确认与重复提交。
- 区分单任务状态与长期偏好，支持用户明确保存和删除成本中心；提供本地网页、锁定依赖与脱离源码目录的安装验证。
- 通过 63 项测试及 Ubuntu/Windows × Python 3.11/3.12 四组 GitHub CI，覆盖授权、制度版本、草稿确认、重复提交、真实 MCP、检查点恢复和 HTTP 接口，并验证 wheel 在源码目录外运行。

真实 Qwen 与模型质量仍待验证，不能写“Qwen 端到端验证通过”或宣称生产上线。跨系统 CI 记录见 [实际运行结果](https://github.com/fangyunok/enterprise-flow-agent/actions/runs/37106022955)。

## 演示顺序

1. Alice 的两笔订单形成草稿，解释每晚住宿上限和超额部分。
2. 在审批处关闭程序、重新运行并登录，恢复原任务。
3. 修改草稿后用旧确认提交，展示版本冲突；刷新后重新确认。
4. 重复提交仅获得一份申请记录。
5. 切换 Bob 或另一租户身份，证明无法访问 Alice 的订单、草稿与任务。

## 面试时要说清楚

这版固定编排流程通过模型提取业务字段；没有让模型直接决定身份、金额或绕过审批。使用关键词制度检索和结构化过滤，没有宣称向量 RAG 或多智能体。演示账号、制度和订单全为自建合成数据；模拟申请编号不是实际审批或付款。
