# 简历与面试材料

## 项目名称

**EnterpriseFlow：企业业务流程编排与执行平台**

技术：Python、LangGraph、MCP、FAISS / Milvus、BGE-M3、bge-reranker、FastAPI、SQLite、Pydantic、Starlette、HTTPX。

## 项目描述

基于 LangGraph 与 MCP 构建企业业务流程编排平台，以差旅费用申请贯通字段补充、制度检索、草稿生成、人工确认与事务提交；使用 SQLite 文件检查点恢复中断任务，身份与金额校验全部落在确定性业务层。

- 将 MCP 工具绑定服务端身份，在数据库查询中按员工、租户、部门和生效日期限制订单及制度，提供适用条款版本与来源对照。
- 实现「结构化过滤 → 向量召回 → 交叉编码器精排」的分层制度检索，编码器与向量库为可替换后端（本地 sentence-transformers / FAISS 或 HTTP 嵌入服务 / Milvus）；168 条条款 226 条查询的评测中 Recall@5 由关键词基线 0.898 提升至 0.987，三种配置越权泄漏均为 0。
- 实现只读 Agent 层：有界 ReAct 规划循环按需查询与核算，对写入工具的提议在执行前被白名单拦下；Supervisor 派发三个最小权限角色做订单核对、条款检索与确定性核算，再对结论做交叉检查并按 blocking / warning 分级。该层输出的 `Proposal` 不带任何业务写入。
- 实现只读制度问答，将授权条款输入模型并校验引用 ID 和原文片段；答案进入人工复核状态，问答链路无法触发业务提交。
- 使用整数分进行费用核算，结合草稿版本、SHA256 内容摘要、来源重校验、写事务和唯一约束处理旧确认与重复提交。
- 提供 FastAPI 服务与 OpenAPI 契约、异步任务提交、依赖就绪检查，以及记录阶段决策点、耗时分布与 token 成本的运行 trace。
- 建立标注集驱动的质量门禁：27 条用例覆盖显式标识、缺失字段、格式噪声、身份伪造与提示注入，输出字段级 P/R/F1、幻觉字段数与弃答率，评测调用与线上同一提取器。
- 通过 182 项测试及 Ubuntu/Windows × Python 3.11/3.12 四组 GitHub CI，覆盖授权、制度版本、草稿确认、重复提交、真实 MCP、检查点恢复、HTTP 接口、检索权限边界、只读规划的预算与越权阻断、多角色的作用域约束与冲突检测，并验证 wheel 在源码目录外运行。

检索与抽取的评测记录见 `results/retrieval_eval.md` 与 `results/model_eval.md`；`fixture` 模式下的确定性指标见 `results/agent_layer_benchmark.md`。跨系统 CI 记录见 [实际运行结果](https://github.com/fangyunok/enterprise-flow-agent/actions/runs/37118933475)。

## 演示顺序

1. Alice 的两笔订单形成草稿，解释每晚住宿上限和超额部分。
2. 在审批处关闭程序、重新运行并登录，恢复原任务。
3. 修改草稿后用旧确认提交，展示版本冲突；刷新后重新确认。
4. 重复提交仅获得一份申请记录。
5. 切换 Bob 或另一租户身份，证明无法访问 Alice 的订单、草稿与任务。
6. 启动 `serve-api`，展示 OpenAPI 契约、跨租户检索隔离与跨身份任务读取被拒。

## 面试要点

架构上的四个选择可以直接展开讲：

1. **模型只做受限字段提取**：模型没有金额、身份、审批许可等输出槽位，`TripFields` 拒绝额外字段，身份、租户与金额由业务服务从数据库裁定并二次校验。
2. **自由规划被限制在只读白名单内**：Agent 层能自主决定「下一步查什么」，写入工具的提议会在执行前被规划器拦下，业务写入路径始终唯一。
3. **权限先于排序**：结构化过滤产出的候选集是检索唯一可排序范围，换编码器、换向量库、加精排都不会扩大可读范围——评测里三组配置的授权候选集完全一致、越权泄漏恒为 0，就是这条不变量的证据。
4. **版本与幂等把住提交口**：草稿绑定版本号与 SHA256 内容摘要，来源变化后旧确认立即失效；提交走写事务 + 唯一约束 + 幂等键，重复提交返回同一编号。

质量工程这条线值得主动讲：召回与抽取都有固定评测集和脚本，指标口径写明（例如 Precision 以模型实际吐出的字段为分母，凭空生成的字段同时计入假阳性与漏检），评测直接调用线上使用的提取器而不是另写一份，因此数字能作为 CI 阈值拦住质量退化。

被追问时不要含糊的两点：

- 测试数是 **182 项**，其中只读规划 24 项、多角色协作 22 项、检索链路 30 项、可观测性 17 项、API 21 项；不要沿用更早的数字。
- 多角色是**确定性路由 + 模型可选提议**：路由依据是已抽取字段，代码在 `Supervisor._route`；模型在 `qwen` / `api` 模式下提议下一步动作，所有提议须先通过白名单与作用域校验。
- 检索的 Recall@1 仍偏低，原因是同租户同部门下「部门专属」与「全员适用」两条条款正文高度相似，需要交叉编码器对限定语做判定——这属于精排层的职责，配置里已预留 `hybrid+rerank` 形态。
